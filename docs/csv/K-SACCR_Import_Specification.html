K-SACCR CSV import specification

CSV contract version 1, for the NettingSets and Trades files whose blank templates end in _v1. The contract version changes only when a column is added, removed or renamed, not with each K-SACCR release.

Files

Each file carries the inputs of one sheet: a record of NettingSets is one netting set, a record of Trades one leg. Import CSV on the staging sheet Import_NettingSets or Import_Trades reads a file; Validate staging checks the staged rows of both against each other and against Params; Commit import then replaces the input sheet. Export CSV template on NettingSets and Trades writes the blank template, the header alone.

File format

  • Encoding. UTF-8, with or without a byte-order mark. A file that is not valid UTF-8, or that contains a NUL character, is rejected. Save the file as UTF-8 text; any language may be used in a text field.
  • Delimiter. Fields are separated by a semicolon, ;. A file whose header is one field holding commas or tabs was saved with another delimiter and is rejected.
  • Quoting. A field that contains ;, a double quote or a line break is enclosed in double quotes, ", and a quote inside it is written twice: "A ""B""" reads A "B". Quotes enclose a whole field only: a quote inside an unquoted field, text after a closing quote, or a quoted field left open at the end of the file is a syntax error.
  • Line endings. Records are separated by CRLF or LF; the last record may end without one. A carriage return anywhere else outside a quoted field is an error.
  • Multi-line fields. A quoted field may span several lines; only text fields accept a line break. A finding names the line on which its record starts and the record number, counted from 1 after the header.
  • Numbers. Decimal point ., no thousands separator, no + sign, no leading zero (0.5 is a number, 007.5 is not), an optional exponent (1.25e6); at most 15 significant digits, so that a value is never rounded when it is read. 1,5 and 1.000,00 are rejected.
  • Dates. yyyy-mm-dd, from 1950-01-01 to 2200-12-31; 31/03/2027 and serial numbers are rejected.
  • Spaces. Spaces belong to the field. A value of a type other than text with a leading or trailing space is rejected, never trimmed.
  • No formulas. Text that starts with =, +, -, @, a tab or a carriage return is rejected, so that no field becomes a formula on a sheet. A negative number is a value, not a formula.
  • Excel. Excel's own CSV save writes numbers and dates in the format of the computer's locale, such as a decimal comma or a day-first date, and in some locales separates fields with commas, so such a file is rejected. Write the file with a program that follows these rules.

Header

The first record is the header. It names every column of the file exactly once, in any order, with the exact lower-case names below; names are case-sensitive. A missing, unknown or repeated column rejects the file before any record is read. There are no optional columns: an optional field is a column whose value may be blank. The column set is the contract version: a file of another version is never mapped by guessing what a column means.

Blank fields, empty files and limits

  • A blank field is an empty one. A required field must not be blank; an optional blank field takes the meaning given under Blank means, which is the sheet's.
  • A blank record, whose fields are all empty, and an empty line are errors.
  • A header-only file is valid and holds no record. Committing it never clears the input sheet: a staging sheet without rows leaves its input sheet as it is.
  • A file is accepted or rejected as a whole: one finding rejects every record, and no record is dropped or truncated.

A file of more than 134,217,728 bytes (128 MiB), a byte-order mark included, is rejected from its size alone. These limits are the import's. The sheets' drop-down lists cover only the rows a user types into, and the calculation reads every row of the input sheets, so they limit neither the import nor the calculation.

Trades file

One record per leg. trade_id is the key: unique in the file and compared case-insensitively. Each leg names its netting set in netting_set_id, which must be a netting set of the NettingSets file, or of the sheet when only trades are imported.

A trade with one risk driver is one record and carries its own MtM: economic_trade_id is blank and mtm_leg is Y or blank. A trade with several risk drivers, such as a cross-currency swap, is one record per leg, all with the same economic_trade_id and netting_set_id: exactly one leg has mtm_leg Y and carries the whole MtM, and every other leg has mtm_leg N and an MtM of 0, so that the MtM is counted once.

A trade settled to market has settlement_type STM and its next_reset_date; it belongs to an unmargined netting set.

Rules between the fields of a record

  • When settlement_type is STM, next_reset_date is required; otherwise next_reset_date is blank.
  • When both are given, end_date is after start_date.
  • When both are given, detachment_rate is above attachment_rate.

Using the examples

The examples are synthetic and hold no real portfolio data. The two belong together: each leg's netting set is in the NettingSets example. To try them, select the text of an example, copy it into a text editor, and save it as UTF-8 with the extension .csv; then import both files and validate them.
