# 🔎 Release audits

Dated reports of the maintenance audit that opens every release
([`RELEASING.md`](../../RELEASING.md#1-run-the-maintenance-audit), step 1). An
audit checks that GitHub tells the truth about the work: issues, PR comments
and review threads, notifications and repository wording. It changes no code,
merges no PR, changes no setting, deletes no branch and publishes nothing.

A report names what was examined and how much, the changes made with their
links, the findings still open and what could not be examined. It is written
once, after the audit, and not edited afterwards; a later audit gets its own
report. The name is `YYYY-MM-DD-vX.Y.Z.md`, after the date of the audit and the
release it prepares.
